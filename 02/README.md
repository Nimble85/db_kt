# Практична робота 2

**Тема:** робота зі СКБД SQLite. Зміна таблиці. Обмеження цілісності: первинний і зовнішній ключі та перевірка. Індекси.

**Мета:** навчитись засобами SQLite змінювати дані в таблиці, забезпечувати цілісність даних, створювати первинні та зовнішні ключі, працювати з індексами.

Консольний клієнт `sqlite3` (SQLite 3.51.0).

## Вимоги до індивідуального завдання (з методички)

> У окремій БД створити 2 таблиці із вказаними обмеженнями цілісності первинного ключа (в кожній таблиці), зовнішній ключ (в одній із таблиць), хоча б однієї перевірки та 2-х індексів (один з яких унікальний).

## Що виконано

**Основне завдання** — `sql/01_main_task.sql`, БД `studentsList.db`:
- `ALTER TABLE`: перейменування таблиці, додавання стовпця;
- первинний ключ: простий, `AUTOINCREMENT`, складений (`passport`);
- зовнішній ключ `students.group_id -> groups.id`, `PRAGMA foreign_keys`, порушення посилальної цілісності;
- обмеження `CHECK` (`age > 0 AND age < 150`);
- індекси: звичайний, унікальний, складений унікальний.

Очікувані помилки (позначені в скрипті коментарями): `UNIQUE`, `FOREIGN KEY`, `CHECK`.

**Індивідуальне завдання** — `sql/02_individual_task.sql`, БД `shop.db` (інтернет-магазин):
- таблиці `categories` і `products` з PK, FK та `CHECK`;
- унікальний індекс по `sku` та звичайний по `name`;
- перевірка обмежень, `EXPLAIN QUERY PLAN`, вибірка з `JOIN`.

## Структура

| Шлях | Призначення |
|------|-------------|
| `report/` | Звіт: `Звіт_ПР2.docx`, `Звіт_ПР2.pdf` |
| `sql/` | Скрипти основного та індивідуального завдань |
| `logs/` | Транскрипти реальних сеансів `sqlite3` (`main_figNN`, `ind_indNN`) |
| `screenshots/` | Знімки консолі, згенеровані з логів, — рисунки звіту |
| `scripts/` | Драйвер сеансів, рендер скріншотів, складання звіту (див. нижче) |

Бінарні `.db` не зберігаються: їх відтворюють скрипти з `sql/`.

## Запуск

```sh
mkdir work && cd work
sqlite3 studentsList.db < ../sql/01_main_task.sql
sqlite3 shop.db         < ../sql/02_individual_task.sql
```
